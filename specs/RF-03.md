# RF-03 · Alta de artista con validación de identidad

## Historia

Como músico quiero darme de alta como artista, con mis datos fiscales, para poder crear campañas. Como administrador
quiero revisar cada alta antes de aprobarla, para evitar campañas falsas.

## Decisiones

- El alta es una **solicitud** que hace un usuario ya registrado (**Cuenta → Perfil de artista**). Al aprobarla, la
  cuenta suma el rol `ROLE_ARTISTA` y sigue siendo fan.
- Datos: nombre artístico, nombre y apellido (como figuran en el DNI), DNI, CUIT, ciudad, provincia y una biografía
  corta.
- Validación automática: DNI de 7 u 8 dígitos, CUIT de 11 dígitos con dígito verificador correcto y que **contenga el
  DNI** (persona humana: `XX-DNI-Y`). DNI y CUIT no se pueden repetir entre artistas.
- Validación de identidad: la hace el administrador a mano (por ejemplo, contra la constancia de CUIT de ARCA). No se
  suben fotos del DNI en el MVP.
- Estados: `PENDIENTE` → `APROBADO` o `RECHAZADO` (con motivo obligatorio). Una solicitud rechazada se puede corregir y
  vuelve a `PENDIENTE`. Una aprobada ya no se puede editar desde la pantalla del artista.
- El artista recibe un mail cuando su solicitud se aprueba o se rechaza (con el motivo).
- El rol nuevo entra en el token al volver a iniciar sesión.
- **La vinculación de la cuenta de Mercado Pago queda para la etapa 6.**

## Criterios de aceptación

- [ ] Dado un usuario sin solicitud, cuando envía los datos válidos, entonces queda una solicitud `PENDIENTE`.
- [ ] Dado un CUIT con dígito verificador incorrecto, o que no contiene el DNI, cuando se envía, entonces se rechaza.
- [ ] Dado un DNI o CUIT ya usado por otro artista, cuando se envía, entonces se rechaza.
- [ ] Dada una solicitud `RECHAZADA`, cuando el usuario la corrige y la reenvía, entonces vuelve a `PENDIENTE` sin
      motivo.
- [ ] Dada una solicitud `APROBADA`, cuando el usuario intenta modificarla, entonces se rechaza.
- [ ] Dado el administrador, cuando lista las solicitudes, entonces por defecto ve las pendientes, de la más vieja a la
      más nueva, y puede filtrar por estado.
- [ ] Dado el administrador, cuando aprueba una solicitud pendiente, entonces el usuario suma `ROLE_ARTISTA` y recibe un
      mail.
- [ ] Dado el administrador, cuando rechaza una solicitud pendiente sin motivo, entonces se rechaza la operación; con
      motivo, la solicitud queda `RECHAZADA` y el usuario recibe un mail con el motivo.
- [ ] Solo el administrador puede listar, aprobar y rechazar (403 para el resto).

## Fuera de alcance

- Vinculación con Mercado Pago (etapa 6).
- Subir foto del DNI o constancia de CUIT.
- Personas jurídicas (CUIT 30/33/34).
