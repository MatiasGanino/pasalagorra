# RF-11 · Stock de recompensas

## Decisiones

- El stock se descuenta cuando se confirma el pago, no al crear el aporte.
- Al confirmar se bloquea la fila de la recompensa (`SELECT ... FOR UPDATE`) y además tiene `@Version`: dos pagos
  simultáneos no venden la misma unidad (RNF-08). La base tiene un `CHECK` de `vendidas <= stock`.
- Una recompensa agotada no se puede elegir. Si dos fans empezaron el pago con una sola unidad disponible, el segundo
  pago que se confirma se reembolsa automáticamente y el fan recibe un mail.

## Criterios de aceptación

- [ ] Dado un pago aprobado de una recompensa con stock, quedan una unidad menos.
- [ ] Dada una recompensa agotada, no se puede aportar por ella.
- [ ] Dados dos pagos pendientes por la última unidad, cuando se confirman los dos, el primero queda aprobado y el
      segundo reembolsado.
